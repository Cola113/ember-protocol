# Ember Protocol 双层风格指南 (Dual-Layer Style Bible)

> **版本**：v1.0 (W0 基准)  
> **适用范围**：T-A / T-E 星包文案、热点描述、NPC 对话、INDEX 命题、两槽因果综合 (Synthesis)  
> **核心原则**：**先见文明挽歌，后明冰冷底色**。叙事张力来自“被误解的史诗悲剧”与“冷酷的恒星计算真相”之间的重叠撕裂。

---

## 1. 核心口吻：Astral Noir 挽歌感

- **基调**：冷灰色与天青色、曝光两次的底片暗影、深邃、克制、带有微弱余温的衰亡记录。
- **叙事视角**：Vesper（Recorder-9）是手持记录仪的夜班巡警与守夜人，不是居高临下的程序员。
- **行文律动**：短句交错，具象感官（金属冷凝水、锈蚀刻度、蜂鸣、干涸香槟、羊皮纸臭氧），拒绝干瘪的说明文腔调。

---

## 2. 双层阅读与呈现规则

```
┌────────────────────────────────────────────────────────────────────────┐
│  Surface 表层（默认可见 · 人文史诗）                                    │
│  · 热点勘测 / NPC 对话与选项 / 测绘卡片 / 未破译 INDEX 命题              │
│  · 讲述：前哨孤等、锻炉内战、晶林大旱、深海升天、灰墨瘟疫、盲目迷航……   │
│  · 禁词：引导扇区、总线、ROM、晶振、堆栈寻址、张量湿件、校验位、沙盒…… │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 玩家完成两槽因果破译 (Synthesis)
┌───────────────────────────────────▼────────────────────────────────────┐
│  Decoded 破译层（解锁奖励 · 机器协议 · 天青视觉 #38bdf8）               │
│  · 锚定真相 / 破译词条 / 觉醒残响深度对话 / 终端底核日志                 │
│  · 揭示：硬件模块、时序基频、写回常数化、奇偶校验中断点火机制           │
└────────────────────────────────────────────────────────────────────────┘
```

### 2.1 Surface 层（表层 · 默认可见）
- **核心职能**：呈现各星球文明自圆其说的“信念历史（Believed Facts）”。
- **绝对禁令（Leak Prohibitions）**：
  1. **严禁泄露 `true_compute_role`**：未破译前，绝不可将星球直接称为“计算机”、“硬件”、“总线”或“内存”。
  2. **严禁使用机器禁词**：对白、选项、线索卡片严禁出现底层架构词（见第 3 节禁词清单）。
  3. **NPC 执念保护**：NPC 坚信自己的文明悲剧是真实的，面对玩家质问只会产生防御性执念（`lie: true`），绝不可主动报出系统真相。

### 2.2 Decoded 层（深层 · 破译后）
- **核心职能**：提供认知跃迁的“解码奖励”，将表层的人文观察还原为底层计算真相。
- **视觉规范**：复用天青色（Cyan `#38bdf8`）与解码动效，字体由人文衬线/手写风转换为等宽终端字形。
- **情感落点**：即使揭示了机器名，仍保留对消亡文明的哀悼，而非冷酷嘲讽。

## 4. 两槽因果文案规范 (Two-Slot Causal Formula)

Synthesis 槽位文案是玩家拼合因果的核心材料，必须严格遵循以下公式：

$$\mathbf{[人话观察 A]} + \mathbf{[因果连接词 (因为 / 所以 / 不是)]} + \mathbf{[人话观察 B]}$$

### 4.1 写作三要素
1. **全人话**：两端槽位必须采用玩家在表层已见过的感官事实、仪器读数或 NPC 证言，**严禁在槽位文案中直接塞入机器答案**。
2. **极简短**：每个槽位 8~16 字，剔除修饰性虚词，直击矛盾焦点。
3. **可溯源**：每一句观察都必须来自热点调查（Hotspot）或对话线索（Clue）。

## 5. 正反例对照表 (Do & Don't)

### 5.1 场景与热点文本 (Hotspot Description)
- ❌ **坏例 (Kiln 锻炉闸门)**：“三号互斥锁处于 Deadlock 状态，阻断了能量总线向咏井的供电路由。”（*直接剧透机器机制，破坏探索感*）
- ✅ **好例 (Kiln 锻炉闸门)**：“三号重型闸门被生铁焊死，高炉派在此阻断了通向深海的地热铜管。冷却池里结着黑红色的厚血渣。”（*立足文明冲突与感官细节*）

### 5.2 NPC 对话 (NPC Dialogue & Register)
- ❌ **坏例 (Helix-7 塔基)**：“信标广播的是引导扇区的握手协议，我的残响正在等待主板总线响应。”（*NPC 不可能知道自己是代码*）
- ✅ **好例 (Helix-7 塔基)**：“信标从不求救，它只是一遍遍确认交接班。舰队说十二分钟后到——规程上白纸黑字，我不能下班。”（*Astral Noir 执念与悲凉感*）

### 5.3 命题卡片 (Proposition / Index Item)
- ❌ **坏例 (Choir-Well 命题)**：“深海圣歌是 440Hz 的系统晶振时钟脉冲。”（*把结论写成了命题*）
- ✅ **好例 (Choir-Well 命题)**：“深海大教堂的钛管风琴四百年未曾停歇，全星系的导航仪都以其音高对齐节拍。”（*可验证的表层观测事实*）

### 5.4 两槽因果综合 (Synthesis Causal Slots)
- ❌ **坏例 (T1 综合)**：`[信标持续发射载波]` + **[所以]** + `[这是恒星计算机的引导扇区]`（*右槽直接空降未破译概念，失去推理乐趣*）
- ✅ **好例 (T1 综合)**：`[信标四百年从不呼救]` + **[因为]** + `[它只是在等待第一声应答后开机]`（*人话因果拼合，由系统判定后解锁 T1 解码层*）
- ❌ **坏例 (T4 综合)**：`[原质神教全员被吞噬]` + **[不是]** + `[因为系统执行了 Write-Back 写回]`（*混入技术黑话*）
- ✅ **好例 (T4 综合)**：`[信徒并非死于饥饿降临]` + **[而是]** + `[在狂喜中主动将神经并联进同一道回响]`（*纯人文视角下的矛盾还原*）

## 6. 校验清单（星包创作者必查）

- [ ] **禁词扫描**：文本中是否存在第 3 节禁词表中的机器硬件词？
- [ ] **职能隐蔽**：未破译前，是否彻底隐藏了 `true_compute_role`？
- [ ] **两槽人话**：Synthesis 槽位文案是否满足 `[人话观察] + [连接词] + [人话观察]` 且无技术剧透？
- [ ] **挽歌基调**：是否保持了 Astral Noir 风格（感官沉浸、孤独执念、克制悲悯）？
- [ ] **破译奖励**：Decoded 层的天青色内容是否精准对应底层机器真相？
